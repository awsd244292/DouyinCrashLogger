## 二、构建链路要点（别踩回去）

- **只产 arm64 单切片**：LLVM 18 的 `ld64.lld` 不支持 arm64e（会静默降级成 `cpusubtype=0x0` 假货），脚本里显式拦死。注入 arm64e 宿主无影响。
- 链接参数：直接调 `ld64.lld`；`-ObjC`；显式 `-framework Foundation UIKit CoreGraphics QuartzCore AVFoundation AudioToolbox`；**不开** `-undefined dynamic_lookup`（缺符号链接期就报）。
- 沙箱本地**没有 iOS SDK**，`ld64.lld` 也不在 → 本地只能做门禁校验，**真机编译一律走 CI**。
- `tools/build_dylib.sh` 的 `FILES=` 列表要随新增 `.m` 同步，否则新文件不参与编译。
- `.github/scripts/build-relevance.sh` 已修：现在认 `tools/**`、`scripts/**`、`DouyinCrashLogger.plist`。注意 **`.github/**` 不在 workflow 触发路径里**，改判定脚本后需 `gh workflow run build.yml` 手动触发。

## 五、真机验证结论（2026-10-13 最新一轮日志）

1. **OC 异常处理器自愈成功**：`self-heal: ... was hijacked, reclaimed` → 健康自检从 `[FAIL]` 变 `[OK]`。上一轮是 `libMetalMetricsInterpose.dylib` 顶掉的。
2. **AVPlayer 实例 0 个，但枚举到 5 个子类**：`HTSMediaMixPlayer`、`ISAVPlayer`、`BDPBackgroundAudioAVPlayer`、`BDByteCastAVPlayer`、`AVQueuePlayer`。
3. 时间线 212 条：全是触摸 + 1 条"即将失活"，**零卡顿、零音频中断**。
4. 内存 973.5 MB，接近 1.2GB 强杀线，本身可能导致播放中断。

### 当前根因判断（重要，尚未修）

"0 个 AVPlayer 实例"**不能证明抖音不用系统播放器**。实例钩子挂在基类 `initWithPlayerItem:` / `initWithURL:`，暂停钩子挂基类 `pause`/`play`；若子类**自己重写 `-pause` 且不调 super**，调用直接走子类 IMP，基类钩子根本不会被经过。`HTSMediaMixPlayer` 命名看是字节自研混合播放器，属于 AVPlayer 家族。

**更可能的真相：钩在父类，抖音用重写过的子类。** 这是可修的。

## 六、待办（下一步，已提出待用户拍板）

对枚举到的每个 AVPlayer 子类单独挂钩子：
1. 每个类保存**各自独立**的原始 IMP（用 `imp_implementationWithBlock` 捕获），避免共享静态变量导致调用链指错；
2. 只对**自己实现了该方法**的子类动手（比对 `class_copyMethodList`），避免往继承链插方法污染行为；
3. 子类 `init` 系列也挂上，把实例检测补实。

改完若 `HTSMediaMixPlayer` 的 pause 命中，就能拿到"谁发起暂停"的调用栈 —— 比系统层侧证硬得多。
完成后按规矩升 **1.4-5** 并出包。
