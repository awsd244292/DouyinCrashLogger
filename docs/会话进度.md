## 二、构建链路要点（别踩回去）

- **只产 arm64 单切片**：LLVM 18 的 `ld64.lld` 不支持 arm64e（会静默降级成 `cpusubtype=0x0` 假货），脚本里显式拦死。注入 arm64e 宿主无影响。
- 链接参数：直接调 `ld64.lld`；`-ObjC`；显式 `-framework Foundation UIKit CoreGraphics QuartzCore AVFoundation AudioToolbox`；**不开** `-undefined dynamic_lookup`（缺符号链接期就报）。
- 沙箱本地**没有 iOS SDK**，`ld64.lld` 也不在 → 本地只能做门禁校验，**真机编译一律走 CI**。
- `tools/build_dylib.sh` 的 `FILES=` 列表要随新增 `.m` 同步，否则新文件不参与编译。
- `.github/scripts/build-relevance.sh` 已修：现在认 `tools/**`、`scripts/**`、`DouyinCrashLogger.plist`。注意 **`.github/**` 不在 workflow 触发路径里**，改判定脚本后需 `gh workflow run build.yml` 手动触发。
- **类结构类错误本地可提前查**：无 SDK 时用桩头（`/tmp/dclstub` 有现值）做 `clang -fsyntax-only -fobjc-runtime=ios-13.0`，
  能抓出 `@class` 前向声明不当（root class / unknown class）这类 CI 才会暴露的问题。桩头需补全用到的 UIKit API。
- **git push 超时兜底**：网络抖动时 git 传输层可能反复超时，但 `gh`（API 层）常仍畅通 →
  用 git Data API 推：create blob → create tree(base_tree=远端tree, 替换改动文件) → create commit → PATCH refs/heads/main。
  推完 `git fetch origin main` 对齐本地引用即可。
- **ObjC 前向声明铁律**：跨类引用时，若该类定义在本文件后半部、前半部就要用到它的**类扩展 / 继承 / @implementation**，
  必须在顶部给**完整 `@interface X : 父类`（含所需属性）**，只写 `@class X;` 会被当成 root class 报错。

## 五、真机验证结论（2026-10-13 最新一轮日志）

1. **OC 异常处理器自愈成功**：`self-heal: ... was hijacked, reclaimed` → 健康自检从 `[FAIL]` 变 `[OK]`。上一轮是 `libMetalMetricsInterpose.dylib` 顶掉的。
2. **AVPlayer 实例 0 个，但枚举到 5 个子类**：`HTSMediaMixPlayer`、`ISAVPlayer`、`BDPBackgroundAudioAVPlayer`、`BDByteCastAVPlayer`、`AVQueuePlayer`。
3. 时间线 212 条：全是触摸 + 1 条"即将失活"，**零卡顿、零音频中断**。
4. 内存 973.5 MB，接近 1.2GB 强杀线，本身可能导致播放中断。

### 当前根因判断（重要，尚未修）

"0 个 AVPlayer 实例"**不能证明抖音不用系统播放器**。实例钩子挂在基类 `initWithPlayerItem:` / `initWithURL:`，暂停钩子挂基类 `pause`/`play`；若子类**自己重写 `-pause` 且不调 super**，调用直接走子类 IMP，基类钩子根本不会被经过。`HTSMediaMixPlayer` 命名看是字节自研混合播放器，属于 AVPlayer 家族。

**更可能的真相：钩在父类，抖音用重写过的子类。** 这是可修的。

## 六、五个迭代版本（v1–v5，全部实现完毕并通过 CI 编译验证）

| 版本 | 主题 | 对标业界 | 解决什么 |
|---|---|---|---|
| v1 | AVPlayer **子类**逐层钩子 + 延迟补挂 | 回放归因 | 破「视频真暂停却没抓到」 |
| v2 | 时间线**落盘** | Crashlytics breadcrumbs | 进程被杀后最后几秒不再蒸发 |
| v3 | 退出性质细化 | KSCrash / Matrix | 把「疑似闪退」拆成 OOM / watchdog / 早期崩溃 |
| v4 | 符号化就绪 | PLCrashReporter | Binary Images 对齐苹果格式 + 补 UUID 与加载区间 |
| v5 | 探针自开销度量 | 业界共识 | 探针不能自己变成卡顿源 |

关键实现取舍（改动前先读，别推翻）：

- **v1 每个类一条绑定记录**、各自持有原始 IMP。共享静态变量会被后挂的覆盖 → 调用链指错。
  只对自己实现了该方法的类动手（`DCLReplaceInstanceMethod` 内部检查），不往继承链插方法。
  查找沿继承链向上，覆盖 KVO 动态子类与迟到子类。
  延迟补挂 1/2/5/10/20s —— **dyld 构造期 AVFoundation 常常还没加载**，那是真漏抓根因之一。
- **v2 常规路径与崩溃路径代码各写各的**。崩溃那条只允许 `open/write/close`，
  数字全自己转十进制（snprintf 不在 async-signal-safe 白名单）。
  另有无锁快照 `DCLTimelineCopyEntriesUnsafe`：崩溃时普通快照那把 unfair lock 可能正被持有，
  抢同一把锁 = 抢救动作把证据全丢。
- **v3 内存口径用 phys_footprint 而非 resident_size**（后者含可回收页会虚高）。
  阈值是经验值并已在结论里附上证据数值，交给人复核。
- **v5 度量本身必须比被度量的还轻**：只做读时钟 + 原子加；
  最大值用 CAS 自旋（普通读改写会让线程互相覆盖，停在偏小的数上，
  而偏小的数恰好让「探针不重」这个错误结论看起来很可信）。

## 六·旧、原待办（v1 之前提出，现已全部完工）

对枚举到的每个 AVPlayer 子类单独挂钩子：
1. 每个类保存**各自独立**的原始 IMP（用 `imp_implementationWithBlock` 捕获），避免共享静态变量导致调用链指错；
2. 只对**自己实现了该方法**的子类动手（比对 `class_copyMethodList`），避免往继承链插方法污染行为；
3. 子类 `init` 系列也挂上，把实例检测补实。

改完若 `HTSMediaMixPlayer` 的 pause 命中，就能拿到"谁发起暂停"的调用栈 —— 比系统层侧证硬得多。
